# Feature parity matrix

This file tracks what pflow-native must reach:

- every user-facing feature of the **pflow.xyz editor**, from `pflow-xyz/public/petri-view.js` v1.28.0 and its sibling modules;
- every tool of the **sim.pflow.xyz MCP server**, from `sim-pflow-xyz/pkg/simmcp` (56 tools);
- the **visualizations and exports** for the data both produce.

How to read it:

- **Source:** where the feature lives today. `pv:` means `petri-view.js` line numbers; `sim_*` is the MCP tool name.
- **Native:** the registry command(s) and/or the view that will carry the feature (see `ARCHITECTURE.md`).
- **Backing:** the pflow-rs crate that does the work. **port** means pflow-rs has no equivalent yet; **remote** means it calls sim.pflow.xyz.
- **Status:** ✅ done, 🟡 partial, blank = planned. Phase 1 shipped in v0.1.0, phase 2 in v0.2.0, phase 3 in v0.3.0, phase 4 in v0.4.0, phase 5 in v0.5.0, phase 6 in v0.6.0, phase 7 in v0.7.0. v0.8.0 added sign-in, the offline build (`services` feature) and the pflow-rs fcb38ac pin (now `fa7b407`, for `IndexedModel` and `BitModel`).

## Phases

| Phase | Theme | Exit criterion |
|---|---|---|
| **1 MVP** | Editor core, token game, ODE, registry + CLI/control/MCP, macros, artifact/view skeleton | Draw, fire and simulate a net on macOS. An agent drives the same commands headless |
| **2 Editor parity** | Everything else in the pflow.xyz editor, plus the web build | A pflow.xyz user loses nothing by switching |
| **3 Simulation workbench** | Rates, scans, sweeps, phase plots, SSA/SDE scenarios, compare, heatmap, optimize | Matches the editor's Analysis workbench and sim's scenario family |
| **4 Analysis & verification** | Incidence, invariants, siphons/traps, reachability, verify, diagnose, canonical/classify | Matches sim's analysis family; results shown on the canvas |
| **5 Data & learning** | Event logs, conformance, calibrate, mining, distill | Matches sim's data family |
| **6 Composition & systems** | Components, compose, extend, diff, bindings, systems, pipelines | Matches sim's composition family |
| **7 Store, share, provenance** | Local CID store, pflow.xyz/sim bridges, publish, knowledge graph, receipts, ZK, LLM tools | Matches sim's store family; signed or proven results |

Every row backed by `remote` (pflow.xyz, sim.pflow.xyz, GitHub), along with the sign-in, `file.open_cid` and `file.permalink`, exists only with the `services` cargo feature. The app and CLI turn it on by default, and `make build-offline` builds without it.

## D. Gaps in pflow-rs (work that lands upstream, not here)

1. ~~Stochastic analysis over `ssa`: contention, depletion, supply kinds, schedules/stages.~~ Landed as `pflow_solver::stochastic`; `sim.scenario` uses it.
2. ~~Siphon and trap search.~~ Landed here (`crates/core/src/analysis/siphons.rs`, a port of sim's `siphons.go` with constraint-driven branching, plus the max-trap fixpoint for Commoner's property). Worth upstreaming to pflow-reachability.
3. ~~Exact automorphisms, canonical labelling, color refinement.~~ Landed here (`crates/core/src/analysis/symmetry.rs`, a string-for-string port of sim's `orbits.go` / `classify.go`, so canonical ids match sim's). Worth upstreaming.
4. Morphism prover/checker. Source: sim `pkg/morphism`. The checker (isomorphism, induced embedding) landed here in `crates/core/src/provenance.rs` (`check_mapping`, no `Session` dependency); the prover is still remote.
5. Port bindings, pipelines, loop fixed point. Source: sim `bindcheck`, `pipeline`, `loop`. Landed here as `crates/core/src/systems.rs` (no `Session` dependency, ready to move upstream).
6. pflow.xyz layout algorithms and URDNA2015 CID sealing. Both landed here instead (`crates/core/src/layout.rs`, `crates/core/src/cid.rs`; the latter is a port of pflow-xyz's json-gold behaviour, not a general JSON-LD library). Worth upstreaming.
7. ~~Deterministic ODE summation.~~ Resolved upstream (pflow-rs `a64067c`, pinned since `fcb38ac`). `pflow_core::PetriNet` keeps transitions in a std `HashMap` with a random hasher, so `pflow_solver::Problem` used to sum derivatives in a different order each run, and results differed in the last bits. The ODE builders now walk places and transitions in sorted order, and `state_labels` come out sorted. Tests that compared two ODE runs with a tolerance now require them to be identical (`sim.compare`'s ODE group, `analysis.diagnose` without noise, `opt.optimize`). Receipts keep rounding ODE results (§B receipt).
8. Weight-0 arcs. pflow.xyz's JS treats an explicit weight `[0]` as "no requirement", while pflow-metamodel's `Arc::effective_weight` maps 0 to 1 (go-pflow's "unset" default). As a result, the gallery's producer-consumer net is dead in go-pflow/pflow-rs and live in pflow.xyz. `sim::executable` drops all-zero non-inhibitor arcs before compiling. Upstream should decide on one meaning, ideally by keeping "absent" and "0" distinct in the parser.
9. ZK circuit soundness (`pflow-zk-arkworks`). `PetriTransitionCircuit` allocates the enabledness remainders and the markings as unconstrained field elements (no range checks), so a proof shows post = pre + C·e_t on committed markings but not that the firing was enabled; read/inhibitor arcs and capacities are not encoded, and the state roots are unsalted. `ArkworksProver::setup` seeds its RNG with a constant (anyone can rebuild the trapdoor), which is why `zk.rs` runs its own setup. Upstream should range-check counts and remainders (bit decomposition), encode tests and capacities, and take an RNG.
10. Gate-aware mining conformance. Before pflow-rs `fcb38ac`, `pflow_mining::check_conformance` treated an inhibitor as a consuming input and a read arc as an output, so `data.calibrate` and `data.conformance` both use the local replay (`crate::conformance`). pflow-rs `a0a2eb1` fixed this, and it is pinned now. Upstream agrees with the local replay on which traces fit when read and inhibitor gates are involved. **It does not make the local replay redundant** for either command; it still differs on:
    - **Capacity:** upstream ignores capacity, as go-pflow does, so a firing past a bound fits.
    - **Weight-0 arcs:** upstream reads them as weight 1 (§D 8).
    - **Token fitness:** on a refused firing, a blocked inhibitor scores 0.5 upstream and 0.0 here.
    - **Activity mapping:** upstream maps by label only; here the id is tried first, then the label (§B, `ActivityMap`).
    - **Extra outputs:** upstream has no variant table, precision sets, residuals or online replay.

    Switching `data.calibrate` back to upstream would bring back the disagreement between the two commands. Keep the local replay for both after the pin bump, or upstream these differences first.
11. RNN games through the metamodel (`pflow-tropical`). `ElmanRnn::play_game`, `self_play_train` and `generate_game_trajectories` fire through `NetMatrix`, which has no inhibitor or read arcs, capacities or colours, and `play_game` has no step cap, so it never returns on a net that does not stop. `commands/rnn.rs` therefore uses only the network (`new` for the seeded weights) and plays its own capped games through `sim::Compiled`; `rnn_net.rs` runs `step` and the three trainers' arithmetic on flat buffers, checked bit for bit against `ElmanRnn`. Upstream could take that layout too. Upstream could take a firing callback (enabled, fire) and a step cap; then `rnn.*` can call it directly.
